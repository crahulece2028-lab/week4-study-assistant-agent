# 4.1 - RAG architecture

## What the system answers

A Study Assistant over **eight ECE lecture-note documents**. The corpus is generated by
`data/build_corpus.py` (reportlab) rather than downloaded, so the repo is self-contained and every
fact a model could retrieve is checkable by eye.

| Document | Topics |
|---|---|
| `01_signals_and_systems` | signals, LTI/convolution, Fourier, sampling & Nyquist |
| `02_digital_electronics` | Boolean algebra, combinational & sequential logic, counters |
| `03_control_systems` | transfer functions, second-order response, stability, PID |
| `04_communication_systems` | AM, FM/Carson, Shannon-Hartley, digital modulation |
| `05_semiconductor_devices` | diodes, BJT, MOSFET, Zener |
| `06_transmission_lines` | Z0, reflections/VSWR, quarter-wave matching |
| `07_microprocessors` | 8051, memory, addressing, cache |
| `08_digital_signal_processing` | Z-transform, DFT/FFT, FIR/IIR filters |

## The pipeline

```
PDF  --PyPDFLoader-->  page Documents  --RecursiveCharacterTextSplitter-->  chunks
     --all-MiniLM-L6-v2 (384-d, L2-normalised)-->  vectors  --FAISS IndexFlatIP-->  index/
```

Built by `src/ingest.py`. Measured on this corpus (`docs/ingest_stats.json`):

| Property | Value |
|---|---|
| documents / pages | 8 / 8 |
| chunk size / overlap | 800 / 150 chars |
| chunks | 27 |
| chunk length | min 153, mean 652, max 799 chars |
| embedding | `sentence-transformers/all-MiniLM-L6-v2`, 384-d |
| index | FAISS `IndexFlatIP`, cosine via normalised vectors |

### Why these choices

- **Local embeddings (`all-MiniLM-L6-v2`, CPU).** No API key, no per-query cost, runs offline. At
  384 dimensions it is small enough that the whole index is trivial and fast (median end-to-end
  query ~26 ms; see 4.3).
- **`IndexFlatIP` + L2-normalised vectors = exact cosine.** It is a brute-force index, which is the
  right call at 27 chunks - an approximate index would add a recall knob for no benefit. The score
  returned by `rag.retrieve_docs` is therefore a real cosine similarity in [-1, 1], not an opaque
  distance.
- **`RecursiveCharacterTextSplitter` with markdown-style separators** keeps each chunk on paragraph
  boundaries where possible, and the 150-char overlap prevents an answer straddling a split from
  being lost.

### A real constraint that shaped the code

This project lives under a path containing non-ASCII characters. FAISS's `save_local` routes through
`faiss.write_index`, whose C++ signature takes a `const char*` and therefore uses the Windows ANSI
code page - it raises `could not open ...: No such file or directory` even though the directory
exists. `src/store.py` works around this by using faiss's **byte** serialisation
(`serialize_to_bytes` / `deserialize_from_bytes`) and doing the disk I/O in Python, which is
Unicode-aware. That is the only reason `store.py` exists as a separate module.

## Retrieval

`src/rag.py` exposes `retrieve_docs(question, k) -> list[dict]`, each hit carrying
`{content, source, page, chunk_id, score}`. `TOP_K` defaults to 4. The dict shape is shared by the
graph, the evaluation and the demo so there is one definition of "a retrieval hit".

## Generation

### One interface, two implementations

`src/llm.py` defines `AgentLLM` with four **decision** methods - `route`, `grade`, `rewrite`,
`generate` - rather than a generic `invoke(prompt)`. The graph calls `llm.grade(...)`; whether that
is a 70B model interpreting a prompt or a local lexical scorer is invisible to the graph. This is
what lets the entire system run and be *evaluated* with no API key, without a fake stub in the
middle.

| Mode | Selected when | Behaviour |
|---|---|---|
| `groq` | `GROQ_API_KEY` set | `llama-3.3-70b-versatile`, temperature 0 |
| `gemini` | `GOOGLE_API_KEY` set | `gemini-2.0-flash`, temperature 0 |
| `offline` | no key | deterministic **extractive** answers |

### The offline model is extractive, on purpose

`OfflineLLM.generate` selects the sentences from the retrieved context that best match the question
(TF-IDF-weighted, IDF computed over the retrieved chunks) and returns them **with a citation**. For a
notes-QA task the facts are in the context, so quoting them is a legitimate answer, and an extractive
answer cannot hallucinate - which makes the evaluation and the failure analysis stable. The mode is
reported in every artifact (`llm_mode`) and surfaced in the demo sidebar; nothing pretends the
offline path is a generative model.

## Grounding

Every grounded answer ends with `[source: <document>]`, and `state["sources"]` carries the retrieved
document names. When retrieval finds nothing and the query cannot be improved (see 4.2), the agent
returns an explicit *"I could not find this in the provided lecture notes"* rather than answering
from parametric memory. That refusal path is scored, not assumed - see 4.3.

## Reproduce

```powershell
python data/build_corpus.py     # -> data/*.pdf
python src/ingest.py            # -> index/faiss_store.bin + docs/ingest_stats.json
python src/graph.py "What is the Nyquist rate and why does it matter?"
```
